# Project-Harness

一套可复用的通用 Harness，用于为不同工程提供一致的协作约定、规则和任务流程。

## 目标

构建一套由稳定通用底座和可选扩展组成的可复用工程协作配置。

## 设计思路

这套配置由两部分组成：通用底座与可选扩展。

- **通用底座**：保存跨工程可复用的工作约定、基本设计原则和通用任务流程。它保持精简、稳定，不携带特定工具、语言或工程的状态。
- **可选扩展**：按实际技术栈和任务需要选用的规则与技能模块。它们可以独立增加、删除或重组，不影响通用底座。

目录中的内容通过递归发现，而非依赖固定文件清单。因此，新增或调整模块后，无需同步维护一份硬编码的索引。

## 目录职责

| 目录 | 职责 |
|------|------|
| `.agents/` | 保存可直接使用的通用底座。 |
| `.agents/rules/` | 保存默认通用规则。 |
| `.agents/skills/` | 保存默认任务流程。 |
| `.agents/extensions/rules/` | 保存已启用的扩展规则。 |
| `.agents/extensions/skills/` | 保存已启用的扩展任务流程。 |
| `humans/` | 保存供人阅读的设计材料。 |
| `rules/` | 保存可选规则的插件仓库。 |
| `skills/` | 保存可选任务流程的插件仓库。 |

从插件仓库选用的模块复制到对应的 `.agents/extensions/` 目录后生效。完整读取时，AI 根据当前实际存在的文件递归发现内容，而不依赖固定文件清单。

## 手动触发与读取约定

不同工具对配置的加载方式并不一致，因此不应默认假设相关内容已经被读取。需要使用通用规则或技能时，由用户明确发起完整读取是稳定的约定。

1. 用户明确发起完整读取。
2. AI 递归读取符合范围的通用配置，并报告本次实际读取结果。
3. 规则和技能按任务需要使用；具体工程的上下文与配置由该工程自身负责。
